The tweakable merge-spine plan

The intervention is chosen: make School Core's candidate → PR → exact-SHA approval/CI → merge → Beads closure path safe. This plan is sorted by what is most likely to change, not by execution order. Read the judgment calls first; the mechanical work can wait.

BLUF: approve the contract, then build one coordinator that refuses to merge or close anything unless the exact candidate SHA has current evidence. The first release should support merge commits only; expand merge methods only after the proof is boring.
ELI10
Think of the merge spine like a luggage tag. Every change gets a tag with its exact fingerprint. Tests, PR checks, approval, merge, and Beads closure must all show the same fingerprint. If the fingerprint changes, the old approval is a stale note—not permission.

A1 · Approval state — atomic CAS, not a boolean read

approval single-use
approval_iduuid
candidate_idfk
head_shaexact
stateissued → consumed
operation_idfk
Only current, unconsumed approval may authorize one merge operation.
PLAN'S PICKCompare-and-set consumption
The boundary

Approval changes from issued to consumed in one atomic operation with the merge reservation. Exactly one worker wins; every loser performs no external write.

Cost: the state store needs a real transaction or compare-and-set primitive. Benefit: duplicate delivery and concurrent workers cannot approve twice.

Pick this if: replay safety is non-negotiable. One line to change it: “use a lease instead of CAS.”

Alternative

Use a short-lived coordinator lease and a consumed timestamp. This is easier to retrofit onto a simple file store, but recovery after a crashed worker is harder and the lease is not the same thing as durable single-use authorization.

Cost: more reconciliation and expiry logic. Benefit: less demanding storage primitive.

A2 · Merge proof — one method first

PLAN'S PICKMerge commit only
The boundary

Start with a true merge commit. Require the PR to report merged, the merge commit to exist remotely, the approved head to be an ancestor, and the first parent to equal the recorded base.

Cost: teams using squash or rebase need a later slice. Benefit: the proof is direct and the first coordinator has one merge semantics to test.

Pick this if: correctness beats breadth for the first production path. One line to change it: “support squash too.”

Alternative

Support merge commit and squash from the first release. Squash requires the first parent/base plus exact tree or patch equivalence; the approved head is not an ancestor and must not be treated as one.

Cost: more proof logic and test fixtures. Benefit: matches common repository policy sooner.

A3 · Authority and out-of-band closure

PLAN'S PICKCoordinator-only writes + reconciliation
The boundary

Only the coordinator may consume approval, request merge, and close the Bead. A close performed by an older path or a human is recorded as an invariant violation and blocks finalization until reconciled.

Cost: recovery requires an explicit reconciliation workflow. Benefit: no legacy shortcut can silently certify a merge.

Pick this if: Beads closure is a result, not an authorization. One line to change it: “allow a named manual override.”

Alternative

Adopt an out-of-band close with an audit warning and let a later merge confirmation repair the candidate record. This improves emergency throughput but makes “closed” temporarily ambiguous.

Cost: weaker invariant. Benefit: humans can unblock a stuck issue without a special tool.

Why step 3 is weak: the current PR helper can publish response-derived artifacts instead of the exact candidate diff. That is why PR publication must be treated as a safety boundary, not a convenience adapter.

Mechanical work (trust me)

These are the pieces that should be boring once the contract is approved. They are listed so the plan does not hide them inside the high-risk slices.

  • operation_id journal and replay tests — duplicate and crash recovery.
  • Fake GitHub client for PR, check, approval, and merge responses — no live mutation in unit tests.
  • Remote graph/tree/patch proof helpers — method-specific merge confirmation.

  • End-to-end fake-GitHub test — candidate through Beads closure.
Current decision: use the recommended paths in A1–A3. The remaining work is implementation, not more policy invention. If a later agent discovers a contradiction, it should record a deviation and stop at the affected boundary rather than silently choosing a new interpretation.
