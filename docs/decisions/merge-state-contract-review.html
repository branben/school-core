Decision queue

7 choices

These are the policy choices the implementation agents should not guess. The recommended option is a starting point, not a decision.

Which GitHub checks are required?

D-01

Missing checks must fail closed. Choose whether School Core names them explicitly or delegates to branch protection.

Recommended: use an explicit required-check list stored with the candidate policy, and fail if the list is empty or unavailable.
Choose one

What exactly can one human approval authorize?

D-02

The approval is consumed atomically and must name one candidate and one exact head SHA.

Recommended: one configured human approval authorizes exactly one candidate SHA, with no reusable “approve the branch” wildcard.
Choose one

Are artifact-only PRs valid golden-path candidates?

D-03

Some existing PR paths publish generated output or a captured patch rather than the exact code diff.

Recommended: reject artifact-only candidates from the code merge state machine; give artifacts a separate review-only terminal state.
Choose one

Which merge methods are allowed initially?

D-04

Each method needs a different machine-verifiable proof. The first implementation should avoid pretending they are equivalent.

Recommended: start with merge commit only; add squash, rebase, fast-forward, and merge queue one at a time with dedicated proof tests.
Choose one

How long should evidence remain durable?

D-05

Evidence must outlive retries and incident review, but the activity log should not become an unbounded secret store.

Recommended: retain candidate, evidence, authorization, and operation records for 180 days; retain redacted summaries longer if needed.
Choose one

Who may invoke merge and closure?

D-06

The current AgentMail poller runs with principal authority. The new coordinator should not inherit that authority accidentally.

Recommended: allow only an explicit repository-and-actor allowlist; the coordinator performs the write after approval verification.
Choose one

What happens if a Bead is closed outside the coordinator?

D-07

Beads is authoritative for closure, but a manual close must not silently certify that code merged.

Recommended: record an invariant violation, block finalization, and require an explicit reconciliation record; never treat the close as merge proof.

WDE amendments

changes required

The latest adversarial pass changed the contract in three ship-blocking ways. These are not optional polish.

Atomic approval

CRITICAL

Approval is a compare-and-set resource. Exactly one worker may consume it for one operation; duplicate delivery performs no external write.

Merge proof

CRITICAL

Merge commit, fast-forward, squash, rebase, and merge queue each require their own machine-verifiable proof. API success is not enough.

CRITICAL
