# Re-hydration guide: rebuild the MCP 07-28 SDK work from a wiped sandbox

**Why this file exists:** every sandbox reset wipes `/tmp/sdk-work`, `/tmp/school-core`,
`~/.local/bin`, and all venvs. This doc is the deterministic rebuild recipe so a fresh
session goes from zero to dual-version-green without re-deriving anything.

## Step 1 — context (2 min)

1. Read this repo's memory if present: workspace `.openhands/memory/` (logs 2026-10-15/16)
   and this doc + the PRD/SPEC in `docs/plans/`.
2. Board: `bd ready` → U1 (`school-core-emb`) is the frontier; U2 `58y` blocked by U1.
3. Upstream issues: software-agent-sdk #6017/#6018/#6019/#6020 (all filed, durable).

## Step 2 — environment (5 min)

```bash
# bd (beads) — for task tracking on this repo
curl -fsSL https://raw.githubusercontent.com/gastownhall/beads/main/scripts/install.sh | bash
export PATH="$HOME/.local/bin:$PATH"

# dolt CLI — ONLY needed to escape Dolt merge conflicts on fresh clones
curl -fsSL -m 120 -o /tmp/dolt.tar.gz \
  https://github.com/dolthub/dolt/releases/download/v2.4.2/dolt-linux-amd64.tar.gz
tar xzf /tmp/dolt.tar.gz -C /tmp && cp /tmp/dolt-linux-amd64/bin/dolt ~/.local/bin/dolt

# GitHub token → git credential store (required for bd dolt push over git+https)
printf 'https://x-access-token:%s@github.com\n' "$GITHUB_TOKEN" > ~/.git-credentials
chmod 600 ~/.git-credentials && git config --global credential.helper store
```

## Step 3 — school-core + board (5 min)

```bash
git clone https://github.com/branben/school-core.git /tmp/school-core
cd /tmp/school-core && bd init          # may appear to hang ~120s; that's normal
bd ready                                # if it says "No ready work", see dolt reset below
```

**If `bd sync`/pull fails with** `local changes would be stomped by merge: events`:
```bash
cd /tmp/school-core/.beads/embeddeddolt/school_core
dolt reset --hard origin/main           # local init commits vs remote → hard reset
cd /tmp/school-core && bd sync          # should print "Sync complete."
bd ready                                # expect U1 emb as the 1 ready issue
```

## Step 4 — SDK worktree + venvs (10 min)

```bash
git clone https://github.com/OpenHands/software-agent-sdk.git /tmp/sdk-work
cd /tmp/sdk-work

# Target venv: fastmcp 4.1.0 + mcp 2.3.0 (Python 3.12)
python3.12 -m venv /tmp/u2venv && /tmp/u2venv/bin/pip install \
  fastmcp==4.1.0 mcp==2.3.0 pytest pytest-asyncio anyio

# Legacy venv: fastmcp 3.4.8 + mcp 1.x (Python 3.13 for mcp1)
python3.13 -m venv /tmp/mcp3venv && /tmp/mcp3venv/bin/pip install \
  fastmcp==3.4.8 mcp==1.28.1 pytest pytest-asyncio anyio
```

## Step 5 — apply the patch set

Apply the **file-change map** from `2026-10-16-002-spec-mcp-0728-upgrade.md` verbatim:
`_compat.py` (new), `utils.py`, `tool.py`, `definition.py`, `oauth.py`, `client.py`,
plus the 5 test files. Key invariants:
- `_compat.py` uses `_MISSING` sentinel (never `or`-chains on falsy modern fields).
- `utils.py` defaults `mode="legacy"` when `FASTMCP_GE_4` (protects #1739 + notifications).
- `client.py::connect()` branches fastmcp<4 vs >=4 (never drop the 3.x session reset).
- `oauth.py` catches `(httpx.HTTPError, httpx2.HTTPError)` guarded.
- The 5 tests are dual-version — no `mcp.__version__` (doesn't exist).

## Step 6 — the gate

```bash
# Both venvs must pass the same 147 tests with warnings as errors
/u2venv/bin/pytest tests/sdk/mcp -q -W error      # fastmcp 4.1.0 / mcp 2.3.0
/mcp3venv/bin/pytest tests/sdk/mcp -q -W error    # fastmcp 3.4.8 / mcp 1.x
```

Lead reconnaissance test: `python3 tests/sdk/mcp/test_oauth.py`.

## Step 7 — after any change (durability)

```bash
cd /tmp/school-core
bd dep add <blocked-id> <blocker-id>   # update U1–U7 graph if you add/close beads
bd dolt push                           # board → GitHub remote (off-workspace durable)
git add -A && git commit -m "mcp-0728: <note>"   # doc updates → this branch
```

## Gotchas (cost real time)

- Env resets wipe `~/.local/bin` (bd, dolt), `/tmp/*venv`, `/tmp/sdk-work`,
  `/tmp/school-core`. Workspace `/.openhands/memory/` and this repo survive.
- `bd init` on a fresh clone may leave `.beads/embeddeddolt` incomplete: delete it and
  re-run `bd init`, or `dolt reset --hard origin/main` for the `events` stomp conflict.
- `dolt` v2.4.2 uses `dolt version` (not `--version`).
- `bd dep add X Y` means `<X> depends on <Y>` (Y blocks X). Reversed args create a
  reversed graph; verify with `bd show`/`bd dep tree`.
- No `mcp.__version__` — version-detect via `FASTMCP_GE_4` on `importlib.metadata`.
