The repo is the reference implementation, not the runtime. The runtime is Hermes dispatched by Orca, with the student's thinking routed through OmniRoute. school-core owns judgment + growth; it does not own the runtime.

L1 Runtime — Orca wired

  • Owns: worktrees (rooms), terminals (desks), schedules, click-to-task.
  • Persistent roles = exactly 3: principal, cto, coo. Students are disposable per bead.
  • Rediscover-before-create for the 3 persistent roles (stops the *-2 suffix leak).
  • Must not own judgment, scoring, curriculum, or the model faucet.

Current seam — PR provider + bridge candidate path under review

This is the boundary that turns a validated candidate into a published provider PR, and the durable school state that must never claim success the provider did not confirm.

AssetOwner / protection
The provider's PR surfaceno duplicate PRs per candidate; no forged / unverifiable success claims
Durable school staterun record, issue close/label, processed checkpoint — must never claim success that the provider did not confirm
Candidate identity(candidate_id, head_sha) binding of everything published

Fail-closed rules that actually matter

  • Journal before write. pr_pending is durably recorded before the provider call. A crash can only leave pr_pending, never a silent gap that invites a duplicate write.
  • Ambiguity never upgrades itself. Only a provider answer bound to (candidate_id, head_sha) — or a recorded pr_published row — turns publication into success. A guess is not reconciliation.
  • Reconcile before retry. A pr_pending row is resolved by asking the provider for the PR bound to that candidate/head. Found → adopt the URL, no second write. Definitively absent → a fresh write is safe. Unknown (no find_pr, provider error) → block; we do not risk a duplicate PR.
  • Idempotent replay. A pr_published row with the same head_sha returns the recorded URL without touching the provider.
  • Pre-write refusals are terminal for that candidate (pr_failed); a retry must be a new candidate, not a re-press of a refused one.

Failure model

FailureExampleOutcome
Pre-write refusalstale head, dirty tree, changed base, digest mismatch, empty diff, branch ownership lostpr_failed — no provider write happened
Write attempted, result untrustworthypublish() raised mid-create, returned None, returned mismatched candidate_id/head_sha, or no valid PR URLpr_pending — outcome unknown
Crash between journal and writeprocess dies after pr_pending is recordedpr_pending — safe: replay reconciles

Capability contract

  • publish_candidate_pr (candidate_pr.py) validates the candidate against its store and extracts the exact base_sha..head_sha diff before any provider call. Provider-write failures raise ProviderWriteError; everything else is a pre-write refusal.
  • publish_candidate_pr_idempotent (pr_provider.py) wraps it with the durable PrStateStore journal and the reconcile-first retry rule above.
  • A CandidatePublisher supplies publish(**request) -> dict. Optional find_pr(repository=, candidate_id=, head_sha=, branch=) -> str | None enables reconciliation; without it, a pr_pending row can never clear (fail-closed).

Source of truth: pr-provider-boundary.md. Non-goals: merge is human-owned; provider selection + live external writes stay a standing human gate; label/color/comment style stays in issue_bridge/pr_creator.

Three invariants to keep the picture honest

  • One authority per concern. bd owns lifecycle; CE owns plan decisions; Orca owns runtime; school-core owns judgment + growth. Bookbag and Kanban must not duplicate bd.
  • Compiler before critic. Mechanical verification runs before subjective review whenever the project can execute the artifact.
  • A report is not proof by itself. The report, branch, commit, base, and inspected artifact must refer to the same work.
