M1 — wrappers in tracing.py

Metadata allowlists

_VIDEO_GENERATE_METADATA_PARAMS = ("model", "seconds", "size")
_VIDEO_EDIT_METADATA_PARAMS     = ()   # edit takes only prompt + video
_VIDEO_EXTEND_METADATA_PARAMS   = ("seconds",)
_VIDEO_REMIX_METADATA_PARAMS    = ()

Base class

Modelled on _ImageBaseWrapper but not inheriting its create/acreate body — the four methods differ in which kwarg carries the prompt and which carries the file.

  • _parse_params reads prompt, routes the file kwarg (input_reference for create, video for edit/extend) through _materialize_logged_file_input
  • _log_result merges timing only — not _parse_metrics_from_usage (D5)
  • _extract_video_output → {id, status, progress, size, seconds, model, error}

Open risk: confirm _try_to_dict handles the Stainless Video model and that error serializes without raising.

M2 — patchers in patchers.py

Four _make_method_patchers calls targeting openai.resources.videos.videos for methods create, edit, extend, remix — each yielding a sync, async, and instance patcher. Then VideosPatcher + _WrapVideos, mirroring ImagesPatcher/_WrapImages.

Both halves, or the guard test fails

test_wrap_openai_and_setup_use_same_wrappers asserts the wrapper sets from OpenAIIntegration.patchers and _WRAP_TARGETS are equal. So: add VideosPatcher to integration.py and ("videos", _WrapVideos) to _WRAP_TARGETS.

Because D1 gives create_and_poll no wrapper, the guard cannot pass while the duplication bug ships — that failure mode needed wrapper reuse, which we do not do.

M3 — tests

The version guard is mandatory

The matrix runs 3.16.2 / 1.92.0 / 1.77.0 / 1.71.0 and only 3.16.2 ships the videos module — verified by unzipping all four wheels. Under CI, record_mode="none", so an unguarded video test fails the three old sessions with "cassette not found" rather than skipping.

pytest.importorskip("openai.resources.videos")

That skips before VCR engages, so no phantom cassette is needed. Cassettes live under casettes/latest/ only; then run check-unused-cassettes.py.

  1. create → span named Video Generation; assert no tokens/cost in metrics (D5)
  2. create with a reference image → input is an Attachment with a reference.content_type (D3)
  3. edit / extend → assert the exact metadata keys, since D2 is the bug this guards
  4. remix → name + remixed_from_video_id
  5. wrap_openai(client) wraps all four (same shape as the existing images test)
  6. setup() patchers resolve Videos / AsyncVideos
  7. The existing wrapper-parity guard still passes

M4 — docs

Nothing enumerates instrumented methods. docs/ holds only publishing and VCR docs; generated_types.json and openapi/ describe the Braintrust API, not the OpenAI SDK. No doc table to update.
