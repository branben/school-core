Instrument the OpenAI Video generation API

PRD · upstream issue #304 · fork branben/braintrust-sdk-python @ 696d206a

status: proposed2026-09-30brownfield openai 3.16.2 / 2.31.0 measured

client.videos.* produces zero Braintrust spans today. It should produce the same span shape client.images.generate() already produces — because Images already does it, and video is the same class of call: a model, a prompt, media out.

The gap

Videos methodWhat it doesInstrumentWhy

Nine patchers ship today — agents.sessions, chat.completions, embeddings, moderations, audio.{speech,transcriptions,translations}, images, responses. Zero video references anywhere in the integration.

Why create_and_poll is excluded — and poll is not

create_and_poll calls self.create(...) then self.poll(...). Wrapping it too would add a parent span saying status: "completed" around a child saying status: "queued".

The repo's cursor_sdk integration faces the identical shape and answers it: it wraps Agent.send and Run.wait as separate patchers, and does not wrap Agent.prompt — the one-call convenience method that does agent.send(message).wait(). Trace the inner pair; leave the wrapper alone.

So poll is in scope. That second span is where completion is recorded — excluding it would leave a trace proving only that the request was accepted.

What the user sees

A span named Video Generation, Video Poll, Video Edit, Video Extend, or Video Remix:

  • input — the prompt, plus the reference video or image as a Braintrust Attachment
  • metadata — provider, model, seconds, size
  • output — video id, status, progress, size, seconds, error
  • metrics — duration, and no cost (Sora is not token-metered; Video has no usage field)

The two traps

One metadata allowlist does not fit four methods

create takes model, seconds, size. edit takes neither. extend takes seconds. remix takes neither. A single allowlist — the natural copy of the images one — silently yields {"provider": "openai"} for two of the four methods. Per-method allowlists.

CI is the hard part, not the code

The nox matrix runs four openai versions. Measured by unzipping all four wheels: only 3.16.2 and 2.31.0 ship openai/resources/videos.py. 1.92.0, 1.77.0, 1.71.0 have none. Under CI record_mode="none", so an unguarded video test fails the three old sessions with "cassette not found" instead of skipping.

Objections, pre-answered

  • "Isn't this copy-paste of Images?" Mostly — and that is the point. The patcher factory already emits sync + async + instance patchers from one callback. The delta is ~120 lines.
  • "Won't this break users on openai 1.x?" No. applies() returns False when the target module is absent, so the patcher is inert. The tests need the guard.
  • "Why not CRUD too?" A span per poll tick buries the generative signal. poll is the exception — it is the one blocking call where generation time is spent.
  • "Why skip create_and_poll? Isn't that the common call?" It is the common call, which is why its two inner calls are each traced. Wrapping the wrapper too would add a third span duplicating the pair. cursor_sdk makes the same call for Agent.prompt.
  • "Related to Google GenAI?" Yes — upstream #236 is the same gap for generate_videos(). Separate issues are fine.

Done means

  • Four methods emit one span each, sync and async, under both entry points
  • File inputs log as Attachment, never a raw handle
  • Video tests pass on latest and skip cleanly on 1.92.0 / 1.77.0 / 1.71.0
  • No cassette and no doc goes stale
