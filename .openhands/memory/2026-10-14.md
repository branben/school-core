## codex-security CI gate — debugging journey (2026-10-14, PR #146)
- Goal (audit bpx): make the scan gate actually fail on findings instead of being decorative/echo-only.
- Three env constraints discovered, in order:
  1. `--output-dir` MUST be outside the scanned git worktree ("Scan artifacts cannot be written inside the protected scan root", exit 2). Was `results/` → moved to `${{ runner.temp }}/codex-security-results`.
  2. `runner.temp` is NOT available in workflow-level `env` — parse-fail signature is workflow run with 0 jobs, status=failure, created==updated same second. Resolve the path per-step instead.
  3. Output dir must be `chmod 700` (private) — runner.temp dirs are created with broader perms.
  4. State dir (CODEX_SECURITY_STATE_DIR) ALSO must be outside the worktree — was `github.workspace/.codex-security-state`.
  5. `ubuntu-latest` (24.04) blocks codex's Bubblewrap sandbox: kernel.apparmor_restrict_unprivileged_userns=1 → "bwrap: loopback: Failed RTM_NEWADDR". MUST use `ubuntu-22.04`.
- After all that: scan RUNS and authenticates, but fails with **"Quota exceeded. Check your plan and billing details."** — OpenAI billing on the `OPENAI_API_KEY` secret. The gate is real now; it's red for billing reasons, not code. PR #146 notes this for the maintainer.
- Practical: to debug a GH Actions step failure, fetch the raw log via `GET /repos/{o}/{r}/actions/jobs/{job_id}/logs` (job id from the run's jobs endpoint). Watch for workflow "0 jobs" runs = YAML/parse error.
- The scan check was ALWAYS red pre-fix too (quota/preflight) — no regression; the gate is now meaningful.
